A clear division of responsibility

One workflow, reusable components.

Prepare the system deliberately, operate the live output explicitly, and keep hardware, control logic and rendering independently maintainable.

01 / SWITCHING

A professional workflow

PGM/PST, NEXT TRANSITION, manual T-bar, cascaded M/Es, independent keyers and DSKs. The initial topology has four M/Es, four upstream keys per M/E and two DSKs.

02 / PREPARATION

Design before going live

Prepare typed inputs, outputs, routing, multiview and reusable SuperSources in the Qt workspace. Physical-panel operation is provided by faderOS.

03 / RENDERING

Native engine primitives

casparMIX adds rendered composition routes, synchronized reentries, native wipes/DME, MOVE and multiview graphics. Mixer decisions stay in kavtor, picture operations stay in the engine.

The render engine extension

CasparCG + casparMIX

An additive, versioned patch set on the pinned upstream stable. Keep CasparCG and its commands while adding reusable native mixer operations. Engine changes remain separate from the control-room logic.

Designed as a patch series

Combined distribution patch, ordered individual patches, checksums and reproducible application against upstream.

Native pixel/audio tests and capacity evidence document exactly what has been checked. Benchmark throughput is not a universal production guarantee.
